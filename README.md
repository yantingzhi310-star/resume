# AI 个人简历网站

一个**单文件**的交互式个人简历网站。深色终端极客风，内置一个能基于简历内容回答提问的 **AI 简历助手**。

没有构建步骤、没有 npm 依赖、没有后端。双击 `index.html` 就能打开。

---

## 快速开始

| 方式 | 操作 |
|---|---|
| 本地查看 | 直接双击 `index.html` |
| 本地服务器（推荐，剪贴板等 API 更完整） | `npx serve .` 或 `python -m http.server` |
| **发布到公网，让别人也能看** | 见 **[DEPLOY.md](DEPLOY.md)** |

### 发布前三步

```bash
node _preflight.cjs      # 自检：内容替换了吗？分享卡片对吗？Key 会不会公开？
node _og-image.cjs       # 按当前简历内容重画分享卡片
# 然后照 DEPLOY.md 走（Netlify 拖文件夹 / Vercel / GitHub Pages 三条路线）
```

`_preflight.cjs` 拦的是最常见也最尴尬的错——**把还没替换的示例人设发到公网**，让招聘方打开看到一份虚构的简历。它没报绿色「可以发布」之前别往下走。

部署需要**两个文件**：`index.html` 和 `og-image.png`。少传后者，分享到微信 / LinkedIn 就没有配图，只有一行干巴巴的文字。

## 管理员模式

按 `Ctrl + Shift + A`，或点页脚右下角的「管理」进入。**首次进入会让你设置一个密码**，之后每次都需要它。

面板里有 12 个分页：基本信息、首屏数字、工作经历、项目作品、技能栈、教育与荣誉、联系方式、AI 助手、常见问答、站点设置、导入 / 导出、安全。

- 所有编辑**实时预览**——改完左边，右边站点立刻变
- 改动自动存为**本地草稿**（存在你这个浏览器的 localStorage 里）
- 点顶栏「导出 index.html」下载一个**已内嵌全部内容的新文件**，替换线上文件即对所有访客生效
- 列表项支持新增 / 删除 / 复制 / 上下排序，项目里的指标卡、技能方向里的技能条目都支持嵌套编辑
- 15 分钟无操作自动锁定

### ⚠️ 这道锁到底有多强，请如实理解

**它不是安全边界，只是一个「访客止步」的门帘。**

本站是纯静态页面。密码的哈希、比对、解锁状态**全部在浏览器里执行**。任何能打开这个 HTML、查看源码或改几行 JS 的人都可以直接绕过它——它甚至挡不住直接编辑文件的人。

它挡得住**随手点开页面的普通访客**，挡不住有心人。所以：

- 不要用它保护真正敏感的数据
- 不要把高额度 API Key 放进去
- 需要真正保密的逻辑，请放到后端接口后面

实现上已经做的：PBKDF2-SHA256（210,000 次迭代 + 16 字节随机盐，不存明文）、失败 5 次后限速（30 秒起，翻倍递增，上限 5 分钟）、会话仅存活于当前标签页、15 分钟空闲自动锁定。**这些防的是「拿到哈希反推密码」和「随手暴力试探」，防不了「绕过校验」。**

### AI 的 API Key 有两种放法

| 放法 | 谁能用 | Key 安全吗 |
|---|---|---|
| 访客自己在页面齿轮里填 | 只有他自己 | 只存他自己浏览器，安全 |
| 管理员在面板里填 + 导出 | **所有访客共用** | ❌ **等于公开**——查看源代码就能拿到 |

面板里的红色警告框会再提醒一次。如果想让所有访客都能用大模型，正确做法是自建一个后端代理接口转发请求，Key 留在服务端。

优先级：访客自己填的 > 管理员烘焙的 > 无（本地检索模式）。

### 忘记密码怎么办

管理员密码只以哈希形式存在，无法找回。三种出路：

1. 能进面板时先在「安全」页改掉
2. 打开浏览器开发者工具，执行 `localStorage.removeItem('resume.admin.v1')`，刷新后重新设置
3. 如果你已经把密码烘焙进导出的文件了，就改回原始文件

## 内容怎么改：两种方式

| 方式 | 适合 | 生效范围 |
|---|---|---|
| **管理员模式**（推荐） | 日常维护，边看边改 | 导出后对所有访客生效 |
| **直接改 `DEFAULT_PROFILE`** | 批量粘贴、版本管理、用编辑器改 | 改完刷新即生效 |

覆盖优先级：**本地草稿（管理员改过）> 烘焙数据（导出的文件）> 文件里的 `DEFAULT_PROFILE`**。

所以：如果你在管理员面板里改过东西，之后又手动改了文件里的 `DEFAULT_PROFILE`，浏览器里的草稿会把手动改动盖住。这时候进「导入 / 导出」页点「丢弃本地草稿」即可。

### 几个要点

- **`faq` 是最值得花时间的字段。** 把 HR / 面试官最常问的问题（期望薪资、到岗时间、为什么换工作、带过团队吗、优缺点…）都写进去。AI 助手会优先匹配这里的答案，命中时准确度最高。
- **项目的 `stack` 和 `tags` 分工不同，两个都要写。** `stack` 填技术名（`TypeScript`、`PostgreSQL`），`tags` 填**这件事本质上在做什么**（`RAG`、`检索增强`、`混合检索`）。AI 助手靠 `tags` 才能把「他 RAG 做到什么程度？」这类概念性提问关联到对应项目上——只写 `stack` 的话，项目里没有「RAG」这三个字，就关联不上。工作经历的 `tags` 同理。
- **写具体数字。** `points`、`highlights`、`metrics` 里尽量带量化结果（QPS、延迟、提升比例、金额）。AI 助手回答时会引用这些数字，有数字的回答比形容词有说服力得多。
- **富文本支持很有限。** 只有 `<b>` / `<strong>` 会生效，其余 HTML 会被转义（这是刻意的安全设计）。AI 答案里支持 `**粗体**`、`` `代码` `` 和 `- 列表`。
- **图标名**取自代码里的 `ICON_PATHS`。想加新图标就在那里加一条 SVG path，然后在 `PROFILE` 里引用它的名字。
- 改完想确认没写错：跑一下 `node _test.cjs`。

## AI 简历助手

### 模式一：本地检索（默认，零配置）

把 `PROFILE` 拆成 30 条知识片段，用「中文 n-gram 分词 + 倒排打分」做检索，再按提问意图合成结构化回答。

- 完全离线，不联网、不需要 API Key、不上传任何数据
- 回答会标注来源章节，点击可跳转
- 知道自己的边界：简历里没写的事会直接说「没有」，不会编

### 模式二：接入大模型（可选，回答更自然）

点 AI 面板右上角的齿轮，填入任意 **OpenAI 兼容**接口即可：

| 服务 | Base URL | 模型名示例 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 阿里通义 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 本地 Ollama | `http://localhost:11434/v1` | `qwen2.5:7b` |

- 填 Base URL 到 `/v1` 为止，程序自动拼 `/chat/completions`
- **API Key 只存在你自己浏览器的 localStorage**，不会发给任何第三方
- 支持真实流式输出（SSE），大模型不可用时会**自动降级**回本地检索，不打断访客

> ⚠️ 前端直连会暴露 Key 给访客。如果是公网站点，建议改成一个后端代理接口，或者干脆只用本地检索模式（对简历场景已经够用）。

## 导出 PDF 简历

点顶栏的打印机图标（或按 `P`），在打印面板里选「另存为 PDF」。

打印样式是单独写的一套：浅色、单栏、去掉所有导航/动画/AI 面板/终端输入行，并强制展开所有内容、避免条目跨页断开——**面向 ATS 和真人 HR 阅读优化**，不是把网页截图塞进 PDF。


跑测试：

```bash
node _preflight.cjs   # 发布前自检（不需要浏览器）
node _test.cjs        # 逻辑层：数据完整性、分词、AI 问答、转义、异常输入

# 浏览器相关的脚本需要先起一个带调试端口的 Chrome：
#   chrome --headless=new --remote-debugging-port=9222 --user-data-dir=/tmp/p about:blank
node _visual.cjs      # 渲染 / 交互 / 主题 / 打印 / 响应式 / 无障碍 / 控制台报错
node _audit.cjs       # 横向溢出、文字裁切、空区块、入场动画
node _admin.cjs       # 管理员模式（会写出 _exported.html 并在浏览器里重新加载验证）
node _crop.cjs        # 对比度审计 + 输出到 _crop/ 的特写图
node _og-image.cjs    # 重新生成分享卡片
```

**测试不依赖具体内容。** 你把示例人设换成自己的真实经历后，测试依然全绿——它校验的是「结构成立、数量自洽、渲染正确」，不是「必须有 6 个项目」。

各脚本覆盖的重点：

| 脚本 | 能发现什么 |
|---|---|
| `_preflight.cjs` | 示例内容未替换、分享卡片地址是占位域名、图与内容不同步、API Key 会被公开、体积超标、知识库为空 |
| `_test.cjs` | 数据字段缺失、图标名无效、分词/检索退化、AI 引用夹杂代码、并列提问只答一半、拼写纠错越界、XSS 转义失效、空输入与超长输入崩溃 |
| `_visual.cjs` | 真实浏览器 JS 报错、元素未渲染、筛选计数与卡片数不一致、空区块、读屏刷屏（aria-live）、交互失效、主题持久化、打印样式 |
| `_audit.cjs` | 四档视口下的横向溢出、文字截断、空区块、入场动画漏触发 |
| `_admin.cjs` | 明文密码落盘、哈希参数退化、编辑不同步、导出文件损坏、烘焙数据泄漏到页面、限速失效、会话语义 |
| `_crop.cjs` | 配色对比度不达 WCAG AA、局部排版问题 |

## 自定义外观

所有颜色、间距、圆角都是 `:root` 里的 CSS 变量（`--accent`、`--bg-base`、`--sp-4`…），改一处全站生效。浅色主题的令牌在 `[data-theme="light"]` 下，打印主题在 `@media print` 里。

- 想换主色：改 `--accent`（深色主题）和 `[data-theme="light"]` 里的 `--accent`
- 想调间距节奏：改 `--sp-1` ~ `--sp-9`（4/8 节奏）
- 换配色前建议跑 `node _crop.cjs`，它会用 WCAG 公式核算所有前景/背景组合的对比度

**无障碍**：正文对比度 16.4:1、次要文字 6.3:1，均远超 WCAG AA 的 4.5:1；支持 `prefers-reduced-motion`；有跳转到主内容的 skip link；弹窗有正确的 `role`/`aria-modal`；图标全部是矢量 SVG 而非 emoji。

## 已知说明

- **唯一的外部请求是 Google Fonts**（Inter / JetBrains Mono / Noto Sans SC）。断网时会自动回退到 Consolas、微软雅黑等系统字体，功能不受影响。想做到 100% 离线，删掉 `<head>` 里那 3 行字体 `<link>` 即可。
- Token 消耗 / 检索质量都取决于 `PROFILE` 写得够不够具体。示例数据是虚构的「陈屿」，请全部替换成你的真实信息。
- 站内示例数据（姓名、公司、数字）**均为虚构**，仅用于演示结构。
